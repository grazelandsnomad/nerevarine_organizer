# 0.73 release notes

Released 2026-10-21. The cycle an installer stopped choosing for a setup it
could not see. A FOMOD that recommends an option "when you have mod X" is now
answered from your mod list and your game, so it no longer pre-selects patches
for mods you don't have or the wrong Fallout 4 build; Start opens Steam when it
is closed instead of losing the game on the way; and a plugin whose master is
missing is left out of the load order, marked red, rather than stopping the
game as it loads. Underneath, the mod list is a model with a view over it and
the window has begun splitting into tested flows, which is what made the fixes
to undo, library moves and the MO2 import small.

## New features

- **Install from Archive…** in the Mods menu: pick one or more downloaded
  archives and install them, the same as dropping them on the window. Until
  now dropping was the only way in.

- **Alt+Up and Alt+Down move the selected mod** one row up or down. Hold the
  key to keep moving; the list is saved once you stop.

## Bug fixes

- **The welcome wizard shows up again after a first run that was cut
  short.** A first run that quit before finishing the wizard left an empty
  mod-list file behind, and that file counted as an earlier setup, so the
  wizard never came back.
- **Qt's own buttons speak the app's language.** The welcome wizard's Next,
  Finish and Cancel, and the Yes / No / OK of every prompt, came from the
  desktop's locale (Catalan buttons on an English wizard). They now follow
  the language the app shows.
- **Start works with Steam closed.** A game started through its script
  extender under Proton (Fallout 4 with F4SE, Skyrim with SKSE) needs Steam
  already running. With Steam closed, the game started Steam itself to have
  Steam relaunch it. The script-extender copy was lost on the way and nothing
  appeared. Start now opens Steam first, waits in a small "Starting Steam"
  window until Steam has signed in, then starts the game.
- **A plugin whose master is missing no longer stops a Bethesda game
  loading.** Reinstalling Vehicle Overhaul Continued activated its Boston PD
  add-on, whose plugin needs a police mod that was not installed, and Fallout
  4 would have crashed while loading.
  - Such a plugin, and any plugin that needs it, is now left out of the load
    order.
  - The mod shows the red missing-masters mark, which Morrowind lists already
    had, with the missing file named.
  - The deploy summary and the status line before a launch say what was left
    out.
  - Each plugin now loads after its own masters. Three mods in that list
    loaded ahead of the plugin they extend.
- **FOMOD options recommended "when you have mod X" are now only
  recommended when you do.** Fallout 4 and Skyrim installers often mark an
  option Recommended only while some plugin is active. The wizard ignored the
  condition, so every such option counted as recommended. Necessity NG-AE
  opened on four wrong picks:
  - the 3DNPC + Scrap Everything version of its Bunker Hill fix, with
    neither mod installed;
  - the RobCo Patcher build, without RobCo Patcher;
  - PRP previs, without PRP;
  - all 24 of its patches ticked. One of them needs prp.esp and ppf.esm, and
    without them the game would not start.

  The wizard now checks each condition against your enabled mods, the
  game's own DLC and Creation Club plugins, the game's version and your
  picks on earlier pages. What the installer recommends for your setup is
  selected, marked "✅ Recommended" and the reason is shown under it. An
  option it holds back names the file it needs. A choice saved from an
  earlier install no longer brings back an option for a mod that is gone.
  When an installer pre-selects an option for a mod you don't have and lets
  you pick none, the wizard now picks None.
- **A FOMOD's conditional files are the right ones.** A condition nested
  inside another lost its last part, so Necessity NG-AE would have installed
  both its PRP and its plain main files, and all three builds of its plugin
  on top of each other. Nested conditions are now read whole, and a
  condition on a file or the game's version is answered too.
- **Fallout 4 installers asking Next-Gen or Anniversary now pick the build
  your game runs.** The FOMOD wizard knew two sides of Fallout 4, the
  original game and everything after the 2024 update, so a choice between
  Next-Gen (1.10.984) and Anniversary (1.11.x) looked like no choice at all:
  the installer's first option stayed selected on an Anniversary install.
  The wizard now reads the build from the game's own executable and selects
  and marks "✅ Recommended" the option for it. When a mod page offers
  Original, Next-Gen and Anniversary files, the file picker recommends the
  one for your game. It used to recommend the Next-Gen file on an
  Anniversary install.
- **Importing an MO2 modlist now links mods to their Nexus pages.** The mod
  id in each mod's `meta.ini` was read under the wrong key and never found,
  so every imported mod got a search link instead of its page.
- **Undo after dragging several mods goes back to before the drag.** A drag
  of several rows used to record one undo step per row, so dragging more
  than ten rows pushed the state before the drag off the undo stack.
- **An answer from Nexus that arrives after its row is gone is now dropped.**
  Removing a mod, switching profile or importing a list while an update
  check, a file-list fetch, a dependency scan or a download was still in
  flight let the answer write to a row that no longer existed, which can
  crash the app. Every row now has an id for the session; a reply names
  the row by it and is dropped, with a line in the log, when nothing has
  that id any more. An undo keeps the ids, so a check started before it
  still lands on the right rows.
- **Moving the mod library no longer freezes the window.** Move Mod Library
  and Consolidate copied on the UI thread, so a multi-gigabyte move across
  drives left the window grey until it finished. Both now run on a worker
  behind a live progress dialog; Cancel stops after the folder in flight,
  and every folder that has landed is already saved.
- **A download is no longer checked against the size of a different file
  from the same mod page.** Updating Faster Decompression on a free account
  failed every time with "680227 bytes, but Nexus says it should be 346773"
  and deleted a good archive: the app had noted the size of the file it
  picked, the download fetched by hand from the website was another file,
  and that note was never cleared. Every such note now names the file it is
  about and is only used for that file; a download of any other file is
  checked by unpacking it instead.
- **Check Updates no longer vanishes into the toolbar's overflow chevron** on
  a 1920 px wide window. The Install archive button that crowded it out is
  gone from the bar (Install from Archive… stays in the Mods menu), and Check
  Updates now sits on its own strip at the right end that the window never
  squeezes. If the bar is still too narrow, the chevron takes buttons from
  the right-hand group instead of this one.
- **BAIN packages are recognised the way Wrye Bash sees them** (GitHub
  issue #2). A package set no longer needs every top-level folder numbered:
  "00 Core" next to "Optional Textures", or plain "Core" and "Optional"
  folders that each hold mod data, open the package picker, and a Docs/ or
  Screenshots/ folder beside them no longer turns the archive into a plain
  install.
- **A crash log now names the functions involved**, so a report with one can
  be acted on.

- **Updating a mod no longer asks whether to replace it.** On a free Nexus
  account an update is fetched by hand: the manager opens the mod page and
  you click "Mod Manager Download". Since 0.72 the mod stays installed while
  you do, so the download that came back met an installed copy and asked
  Merge / Install separately / Replace - though an update can only mean
  Replace. The download you were sent to fetch now replaces the mod without
  asking; any other file from the same page still asks.
- **Big zip archives no longer fail as "corrupt" and get thrown away.**
  Updating Sim Settlements 2 - Chapter 3 (a 5.6 GB zip) downloaded the whole
  file, said it was corrupt, deleted it and left the mod on its old version -
  every time. The download was fine: `unzip`, the only tool the manager used
  for zips, misreads some archives over 4 GB. A zip that `unzip` can't read
  is now unpacked with 7z, as RAR archives already fall back from unrar, and
  only a zip neither can open counts as broken.
- **The Dark mode button showed an empty box in the AppImage.** Its label
  started with the crescent-moon emoji, which only a colour emoji font has.
  The AppImage runs Qt 6.4, which looks for a missing character in at most
  255 fallback fonts and on a machine with many fonts never reaches the
  emoji font; the plain binary on a newer system Qt picks the emoji font
  directly. The label now uses a plain moon symbol (☽) that the common text
  fonts carry, like the ☀ of the Light mode label.
- **The welcome wizard now appears on a first launch.** It never had: the
  app creates its default OpenMW profile on the first start and then took
  that saved profile as proof of an earlier setup, so a new user never got
  to pick a mods folder or paste a Nexus key. It shows once, its first
  page's Next button is enabled (it never was, with a single game to pick),
  and the desktop-shortcut and missing-tools prompts wait for it instead
  of stacking on top of it. Its long lines wrap instead of being cut off,
  and unticking "Register nxm:// handler" is now respected: the app no
  longer takes over Nexus download links on every launch regardless.
- **No red "Could not save openmw.cfg" banner on a machine where OpenMW has
  not run yet.** The config folder is created when it is missing.
- **The archive-tools warning only asks for what is really missing.** With
  7z installed it no longer asks for unzip and unrar, which 7z covers; it
  still asks for unrar when the installed 7z cannot read RAR.
- **"More games…" no longer claims only OpenMW is supported.** It says
  that the games in the menu are the ones this release manages.
- **The window title shows the version**, so a report can say which build
  it is about.

## For developers

- The build compiles with `-Wall -Wextra -Wshadow` and friends, and CI treats
  a warning as an error (`-DNRV_WARNINGS_AS_ERRORS=ON`); a local build leaves
  that off.
- Everything but `main()` is one static library, `nerevarine_core`; a test is
  one file linked against it, declared with `nrv_test()` in
  `tests/CMakeLists.txt`.
- The Windows cross build (MXE toolchain, `build_cross.sh`) and the leftover
  Code::Blocks files are gone; the project builds on Linux only.
- `.clang-format` describes the existing style, for `git clang-format` on
  changed lines.
- `NexusController`, `DownloadQueue` and `BulkInstallQueue` name rows by
  `ModRole::RowId` (`mod_row::rowId`, a session `QUuid`) and never hold a
  `QListWidgetItem*`; `MainWindow::rowById` resolves an id at the moment of
  use, including rows parked across a profile switch.
- The mod list is a `ModListView` (a `QListView`) over `ModlistModel`, a
  `QAbstractListModel` of `ModEntry` rows: one copy of the rows, read and
  written by the window through `ModRow` handles (model + session row id)
  that never dangle. `ModEntry::roleData` is the one mapping between roles
  and fields; the delegate paints from the index as before. The
  `QListWidget`, its items and the item bridge are gone; undo, the filter
  bar, the sorts and the queues work on the model.
- The window hands whole concerns to flow objects that reach it only through
  `WindowShell`, an interface of what a flow may ask of the window:
  `ImportFlow` (the imports and the export; parsing in `import_formats`),
  `DeployFlow` (Bethesda deploy, the deploy hint, the script-extender check,
  every launch) and `LibraryFlow` (Move Mod Library, Consolidate, Clean Up
  Mod Folders). Each has tests over a fake shell (`tests/fake_shell.h`).
- FOMOD conditions are read as a tree (`fomod_conditions`: `<dependencies>`,
  `<dependencyType>`) and answered three ways, Unknown deciding nothing,
  against what `fomod_facts` says the profile holds. `install_layout::
  deployRoot` is the one rule for which folder a mod deploys from; deploy
  had two copies of it.
- `plugins::readMasters` reads a plugin's masters from its header record,
  TES3 and TES4 alike (`plugin_records::headerMasters` is the one TES4
  parser, `XXXX` sizes included). `bethesda_loadorder::settle` holds back
  plugins with a missing master and puts each after its masters. The
  missing-masters scan covers the Bethesda games. `steam_client` says whether
  Steam is up, from `registry.vdf` and `steam.pid`.

## Migration notes

- The plain binary keeps its mod lists and settings next to itself. Unpack
  0.73 over the 0.72 folder, or copy `modlist_*.txt`, `loadorder_*.txt` and
  `nerevarine_prefs.ini` across, to keep your list. The AppImage keeps its
  state under `~/.local/share/nerevarine` and needs nothing.
