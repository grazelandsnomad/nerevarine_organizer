# 0.71 release notes

_In development._ Changes land here as they're committed; this file becomes the
GitHub release body when `v0.71` is tagged (release.yml reads it by version).

## New features

- **The install wizard shows each option's picture.** FOMOD authors attach a
  screenshot to their options - for a retexture installer offering "Option 1"
  through "Option 4", the picture IS the option - and the wizard used to drop
  every one of them: the `<image>` element was never parsed, so you picked
  textures blind. Installers that declare images now get a preview pane
  beside the steps that follows the pointer: hover or select an option and
  its screenshot, name and description appear; a new page opens on its
  current answer's image rather than the previous step's; an option with no
  picture says so instead of showing a stale one. Image paths resolve
  case-insensitively (authors write `fomod\Images\X.JPG`, archives hold
  `fomod/images/x.jpg` - on Linux that match has to be earned), and
  installers with no images keep their old compact shape. **Click a preview**
  and it opens in its own window at full size, the way a Nexus mod page's
  lightbox does: a small screenshot is smoothly upscaled (up to 2x) to make
  use of the screen, a large one arrives whole, and clicking a shrunk one
  switches to the file's actual pixels with scrollbars - **drag to move the
  image around**, and click without dragging to go back to fitted. The window
  is modeless, so you can leave it open and keep clicking through the options.

- **The missing-requirements dialog now reads the mod page's own structure.**
  Installing a mod whose description links other mods used to produce one flat
  wall - Vehicle Overhaul Continued links 38, and every one was announced as
  "may be required" - when the page itself separates a handful of hard
  requirements from patch targets and the author's other mods. The dialog now
  lists the hard requirements first, each with a green tick and the name from
  your own list when you already have it, then the optional and other linked
  mods under a separate header, so "which of these actually matter" stops
  being homework. The classification comes from the description's own section
  headings and inline notes ("optional", "required if you use X"), read
  conservatively - a page with no such structure shows exactly the flat list
  it always did.

## Bug fixes

- **Cancelling an install no longer throws the download away.** Backing out of
  a FOMOD or BAIN wizard deleted the archive it had just downloaded, so trying
  again pulled the whole file down a second time - painful on a half-gigabyte
  mod, and worse without Nexus Premium. Cancelling now keeps the archive and
  installing again reuses it, skipping both the transfer and (when the manager
  remembers the file from this session) the trip through the browser. Failed
  downloads are still deleted, because a suspect file must not be reused, and a
  successful install still cleans up after itself, so archives do not pile up.

- **Modlist Summary no longer freezes the window while it measures.** Working
  out how much disk your mods use means stating every file in every mod folder
  - 30 GiB and **5.2 seconds** on a real list, with a warm cache. The async size
  scan usually gets there first, but it is debounced and takes about as long, so
  opening the summary in the first seconds after launch, or after installing
  something, locked the window up for the whole walk. It now measures on a
  worker behind a cancellable progress dialog that a warm cache never even
  shows; cancelling gives you the counts with the byte totals left out rather
  than nothing.
