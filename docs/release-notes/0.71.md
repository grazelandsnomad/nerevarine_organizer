# 0.71 release notes

_In development._ Changes land here as they're committed; this file becomes the
GitHub release body when `v0.71` is tagged (release.yml reads it by version).

## New features

- **The install wizard shows each option's picture.** FOMOD authors attach a
  screenshot to their options - for a retexture installer offering "Option 1"
  through "Option 4", the picture IS the option - and the wizard used to drop
  every one of them: the `<image>` element was never parsed, so you picked
  textures blind. Installers that declare images now get a preview pane
  beside the steps that follows the pointer: hover or select an option and
  its screenshot, name and description appear; a new page opens on its
  current answer's image rather than the previous step's; an option with no
  picture says so instead of showing a stale one. Image paths resolve
  case-insensitively (authors write `fomod\Images\X.JPG`, archives hold
  `fomod/images/x.jpg` - on Linux that match has to be earned), and
  installers with no images keep their old compact shape. **Click a preview**
  and it opens in its own window at full size, the way a Nexus mod page's
  lightbox does: a small screenshot is smoothly upscaled (up to 2x) to make
  use of the screen, a large one arrives whole, and clicking a shrunk one
  switches to the file's actual pixels with scrollbars - **drag to move the
  image around**, and click without dragging to go back to fitted. The window
  is modeless, so you can leave it open and keep clicking through the options.

- **A translation now says which mod it translates.** Installing a Spanish
  version alongside the mod it translates already cleared the source's "no
  translation" warning, but nothing on screen said the two rows were related
  or which was which - the manager worked it out and kept it to itself. The
  translation row now carries a purple "translation of <mod>" caption. Which
  side is the translation is decided by the language of the text, so two
  English mods that merely share records - a compatibility patch and the mod
  it patches - are never labelled; when the language cannot be told, nothing
  is claimed. Right-click offers **This is a translation of…** to set the link
  by hand for pairs the scan cannot see, and that choice outranks the scan and
  survives a restart.

- **Fallout 4's script-extender build is chosen from the game you have
  installed.** An installer offering "OG" / "AE" / "None" was left on its own
  default, because the manager decided runtimes from the game profile - which
  works for Skyrim, where AE and SE are separate profiles, and cannot work for
  Fallout 4, where one profile covers both. It now reads the version out of
  `Fallout4.exe` and looks for the script extender beside it, so an install
  reporting 1.11.240 with `f4se_1_11_240.dll` present arrives on **AE** with
  the version it matched shown on the row. With no extender in the game folder
  it picks "None" instead and says why, since a plugin built for F4SE would
  never load without it. The same knowledge now guides the download picker
  when a mod page offers one file per runtime.

- **The install wizard decides FOMOD options from what you actually have.**
  Installers ask questions the manager can already answer by looking at your
  mod list, and it now answers them instead of leaving the author's defaults
  standing. A patch named after a mod you do not have arrives unticked and
  says which mod is missing (Vehicle Overhaul Continued pre-ticks eighteen of
  them). A group offering the game's own data against a mod-provided
  alternative picks the base game when that mod is absent - Bethesda Previs
  rather than PRP. A mod offered with and without a framework picks the half
  that matches your list, so Base Object Swapper being installed selects the
  variant that uses it. Every one of those choices carries a plain-language
  note under the option explaining what the framework is and why the choice
  was made - "PRP = Previs Repair Pack - rebuilds the game's precombined
  meshes and visibility data" - because an acronym on a radio button is not an
  explanation.

- **Requirements now come from the author's own list, not just the
  description.** A mod page's Requirements table - the one Nexus shows before
  every download, with the author's notes on each entry - was invisible to the
  manager, so a hard requirement the author listed but never linked in the
  description went unmentioned. Vehicle Overhaul Continued lists Baka
  Framework as "Hard Requirement. Necessary for Base Object Swapper", and
  nothing said so. That table is now read, the author's note decides whether
  an entry is hard or optional, and the note itself shows in the row's
  tooltip. The dialog splits into three sections - needed, optional, and
  merely linked - and shows them whenever the author marked *anything*, not
  only when something is mandatory: Necessity - Nexus Essentials Merged marks
  seven entries and calls every one optional, which is exactly the case worth
  showing, since it means the other 151 links are nobody's problem. Rows are
  also named in a single request now instead of one per link; on that mod the
  dialog used to fire 158 API calls to open, against a non-premium allowance
  of about a hundred an hour.

- **The missing-requirements dialog now reads the mod page's own structure.**
  Installing a mod whose description links other mods used to produce one flat
  wall - Vehicle Overhaul Continued links 38, and every one was announced as
  "may be required" - when the page itself separates a handful of hard
  requirements from patch targets and the author's other mods. The dialog now
  lists the hard requirements first, each with a green tick and the name from
  your own list when you already have it, then the optional and other linked
  mods under a separate header, so "which of these actually matter" stops
  being homework. The classification comes from the description's own section
  headings and inline notes ("optional", "required if you use X"), read
  conservatively - a page with no such structure shows exactly the flat list
  it always did.

## Bug fixes

- **A finished translation is no longer called untranslated.** The coverage
  scan judged a mod on every string in its plugin, including the base game's
  own settings that a mod's editor re-saved by accident - Daedric Maul carries
  72 of them - so it compared 27 strings where the editor offers 2, found 25
  identical, and threw out the user's finished translation as a near-copy of
  the original. The scan now judges a mod on its own words, the same filter the
  translation editor already applied, so the two halves of the app finally
  agree about what a mod contains.

- **A mod whose only text is a name is no longer flagged.** A single invented
  word in a display name - a creature called "Veythrazel" - is that creature's
  name in every language, so there was never a translation to be missing. Mods
  whose entire content is one such name stop being reported as untranslated.
  Multi-word names are untouched: "Ceremonial Morag Tong Blade" is a real item
  name and still counts.

- **A localized plugin's string table is found under either name Bethesda
  gives it.** Skyrim writes `Skyrim_English.STRINGS` and Fallout 4 writes
  `Fallout4_es.STRINGS`, and only the first spelling was recognised - so on
  Fallout 4 a fully translated plugin was reported as having no translation.

- **Spanish: Narsis, and the word for everyone who is not from there.** Eight
  terms added to the English-to-Spanish table so a mod naming the same place
  twice stops getting it translated two different ways: the Narsis districts
  (Grand Bazaar, Market Quarter, Council Quarter, Foreign Quarter, Waterfront),
  Mournhold's Great Bazaar, and Outlander.

- **Cancelling an install no longer throws the download away.** Backing out of
  a FOMOD or BAIN wizard deleted the archive it had just downloaded, so trying
  again pulled the whole file down a second time - painful on a half-gigabyte
  mod, and worse without Nexus Premium. Cancelling now keeps the archive and
  installing again reuses it, skipping both the transfer and (when the manager
  remembers the file from this session) the trip through the browser. Failed
  downloads are still deleted, because a suspect file must not be reused, and a
  successful install still cleans up after itself, so archives do not pile up.

- **Modlist Summary no longer freezes the window while it measures.** Working
  out how much disk your mods use means stating every file in every mod folder
  - 30 GiB and **5.2 seconds** on a real list, with a warm cache. The async size
  scan usually gets there first, but it is debounced and takes about as long, so
  opening the summary in the first seconds after launch, or after installing
  something, locked the window up for the whole walk. It now measures on a
  worker behind a cancellable progress dialog that a warm cache never even
  shows; cancelling gives you the counts with the byte totals left out rather
  than nothing.
