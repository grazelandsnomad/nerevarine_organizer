# 0.75 release notes

Released 2026-11-18. The cycle the library stopped needing you to tidy it. A
mod's folder is named after the mod, whichever installer it came through, and
a tool offers to rename the ones already there; folders you make or copy into
the mods directory are picked up on their own, switched off, with nothing to
click and nothing that deletes anywhere near it; Clean Up moves folders to the
Trash instead of deleting them; Enable All and Disable All arrived. Start now
says when the game died on the way up instead of returning in silence, and a
download for a page you have two mods from goes into the right one. Four
things people reported got fixed: a grass remover was forced to groundcover
and never ran, dark mode threw away separator colours, a separator added over
a filtered list took rows you could not see, and the coloured toolbar buttons
were unreadable on a dark theme. Cyberpunk 2077 gains a deploy, tested only
against a mock install so far.

## New features

- **Every mod gets a folder named after the mod.** Why one mod landed in
  `nerevarine_mods/OAAB Tel Mora` and the next in
  `nerevarine_mods/1d17186d-…/Watercraft` was two different rules: a mod with
  a FOMOD or BAIN installer had its folder named after the mod, while a plain
  archive was named after the file it was downloaded as - and a Nexus download
  can arrive as a bare id with no name at all. Both now go the same way, and
  the folder the archive happened to be wrapped in is unpacked rather than
  kept, so a mod is one folder. The real file name is read from Nexus too, so
  a kept archive is readable as well.
- **Mods → Tidy Mod Folder Names…** offers to rename the folders you already
  have that are called after a download rather than a mod. It previews every
  one first, leaves alone any it cannot name, and the modlist follows them.
  It refuses while a Bethesda deployment is in place, since that records where
  each folder is.
- **Enable All, Disable All, and Enable/Disable Selected**, asked for against
  MO2. "All" means every mod, or just what is shown when the filter box has
  text in it, so a filtered list cannot be switched off by surprise. Both are
  one undo step, one question if something depends on what is being turned
  off, and the window no longer does a full pass over the list per row - a
  few hundred mods used to be enough to lock it up.
- **Folders you put in the mods directory yourself are picked up on their
  own.** No button and no dialog: make or copy a folder into your mods
  directory and it appears in the list, the way Mod Organizer picks one up on
  a refresh. It happens when a profile loads and when the window comes back to
  the front, so it is there right after you make it. New rows arrive
  **switched off**, so a folder turning up can never change what the game
  loads, and if you take one out of the list while keeping its files it is
  remembered and never offered again.

  0.74 could already adopt such a folder, but only through Mods → Clean Up Mod
  Folders - a dialog whose other button deletes. The reporter who asked for
  this said, fairly, that he was afraid to go near it. Nothing about adding a
  folder goes near deleting any more; and because an adopted folder is a mod
  in use, the cleanup sweep stops listing it at all, so it cannot be caught by
  a stray click there either.

  It stays quiet while a download or an install is running, when a sibling
  profile's modlist could not be read, and when so many folders come back
  unused that a modlist has probably failed to load - in each of those cases
  "unused" is not evidence of anything.
- **Clean Up Mod Folders moves folders to the Trash**, where the drive
  supports it, so a wrong click can be undone from your file manager. The
  dialog says which it will do before you confirm, including that the space is
  only freed once you empty the trash. A folder that cannot be moved is
  reported and left alone - never deleted instead.
- **Clean Up Mod Folders no longer freezes the window.** It measures every
  unused folder to show you what you would reclaim, and did that on the
  interface's own thread: on a large library on a slow disk the window locked
  up until it finished. The measuring now runs in the background.
- **Start says when the game did not survive.** Pressing Start and getting
  nothing back was the worst failure the app had: twice the game died during
  start-up - once because Steam was closed and the script extender's instance
  was lost, once because a mod's broken records crashed the data load - and
  the window said nothing at all, so finding out took a Proton trace. A launch
  is now watched: if the game never appears, a banner says so, and if it
  appears and is gone again within a minute and a half, a box names how long
  it lived and shows what the script extender's log ends with, whether that
  log grew at all, and any crash log a crash logger has just written. A
  session that lasted is never reported, and the box says plainly that
  closing the game yourself is not a fault.
- **Settings → Register nxm:// handler.** Clicking "Mod Manager Download" on
  the Nexus website only reaches Nerevarine when it owns `nxm://` links, and
  the only place that was ever offered was a checkbox in the first-run wizard:
  clearing it, or a desktop that lost the association, left the website button
  doing nothing with no way back. The entry registers it again and says so.
  The "Nexus Premium required" box now points at it, and says that the website
  route still needs your API key - the link only names the file.

- **Cyberpunk 2077: Deploy mods to game.** The game has been in the list since
  0.70, but only as a library and a Start button - nothing ever reached the
  game, because it is not a Data/ game and the deploy had nothing to aim at.
  Cyberpunk mods overlay the install folder itself: `archive/pc/mod/` for the
  archives nearly every mod ships, `r6/scripts/` (redscript), `red4ext/` and
  `bin/x64/plugins/` (Cyber Engine Tweaks), `mods/` (REDmod). Deploy now links
  the enabled mods into the game folder that way, in list order, and the
  wrapper DLLs the mod loaders put beside the game's exe (RED4ext's
  `winmm.dll`, CET's `version.dll`) are registered with the Proton prefix, as
  Dark Souls II's already are. A mod that is nothing but an `archive/` folder
  keeps it as its top level at install, so the overlay lands
  `archive/pc/mod/…` and not `pc/mod/…`.

  **Built against a mock install - the game is not on the machine this was
  written on.** It is tested end to end on a copy of the Steam layout, which
  is why it stays behind Settings → Show all games (experimental). If you run
  it on a real install, Mods → Inspect deployment and a note of what happened
  would settle it.

## Bug fixes

- **Oblivion, Fallout 3 and New Vegas: the active plugin list goes into the
  file the game made.** Those games create their own `plugins.txt` and ask for
  it the Windows way, without case; the deploy always wrote `Plugins.txt`, so
  on a disk that keeps case the game could end up with two lists and read the
  old one. The deploy now writes to the file as the game spelled it, and
  Inspect deployment says when a second spelling sits beside it.
- **A plugin that DELETES grass is no longer treated as grass.** Anything with
  "groundcover" in its file name was forced into `groundcover=`, deletion
  plugins included - the `deleted_groundcover.omwaddon` that Groundcoverify
  and Greenmote produce matched on every save. A groundcover plugin is left
  out of the effective load order, so its deletions never ran and OpenMW
  Launcher showed it unticking itself. A name that says it removes grass now
  counts as content, and answering "No" to "handle this groundcover mod
  automatically?" finally sticks - it used to be stored as nothing at all, so
  the next save guessed from the name again. For anything the guess still gets
  wrong, a mod's right-click menu has **Not a groundcover mod**. Also, a mod
  library kept under any folder called "grass" no longer marked every plugin
  inside it as groundcover: the rule reads the plugin's own folder name now.
- **A hand-downloaded update replaces the mod instead of adding a second
  row.** Some Nexus files have no "Mod Manager Download" button at all - the
  author switches it off per file (Tamriel Rebuilt's main file is one) - so the
  only route is Manual download and dropping the archive on the window. The
  drop only ever rejoined a row that was still waiting to be installed; for a
  mod already installed it added the new version as a second row at the
  bottom, with the old one still in place and still flagged. The archive's
  Nexus id is now matched against installed rows too: a row waiting for that
  update after the "Premium required" box is replaced without a question, and
  any other installed match gets the same Replace / Merge / Install separately
  choice a mod-manager download gets. The "Premium required" box now says so.
  Nexus's newer download file names (`Name 26.11.01 42145 26.11.2
  2026-11-01T22-25Z H0S90o2b.7z`, no dashes, no timestamp) are recognised as
  well; before, such an archive was never matched to anything.
- **A download for a page you have two mods from goes into the right one.**
  A page shipping a main file and an optional one (Tamriel Rebuilt and its
  music) gives two rows on the same mod page. When both were waiting for an
  update and the music file came back through "Mod Manager Download", the
  app put it into the **first** row of that page - the main one - and purged
  the main's folder as "the previous version". The link that comes back is
  now matched to the row that was waiting for exactly that file, and whenever
  a page has several rows and the file alone cannot decide, the Replace /
  Merge / Install separately question lists them and asks which one.
- **Separator colours stay the colours you chose in dark mode.** A label that
  stopped reading on the darkened band was swapped for a fixed light grey; a
  dark label on a pale preset (Audio, Characters, most of them) always was, so
  those labels lost their colour on every theme switch. The label is now
  lightened just far enough to read, hue and saturation kept - a purple label
  stays purple. The grey that every separator wears while a mod anywhere has
  an update waiting is a different thing and is deliberate: it says something
  is unfinished, and it comes off the moment the last update lands. What is
  new there is a small green arrow beside the name of the section that holds
  the update, so the grey also tells you where to look, and the grey now
  lasts through a manual download as well, not just the automatic one.
- **"Add separator above" with a filter typed no longer takes rows you cannot
  see.** The filter hides non-matching rows the same way a collapsed section
  does, and the separator went in above the row you clicked without looking:
  every hidden row below it, up to the next separator, quietly changed
  section. Adding a separator now clears the filter first and says so, so the
  list it lands in is the one on screen. The same rule now reads the
  favourites-only star as a filter too: Enable All / Disable All with the
  star on act on the favourites shown, not on the whole list.
- **The coloured toolbar buttons read on a dark theme.** Start, Dependencies,
  Sort with LOOT, Separator, Sort Separators, Forbidden Mods, Modlist Summary
  and the rest set their colour once, for a light surface - dark green, dark
  purple and the like - and kept it on the dark palette's near-black bar, where
  several were close to invisible. 0.70 fixed the Profile picker and the theme
  button; these were still hardcoded. Each colour is now lightened with its
  hue kept whenever the window background is dark, so the buttons stay the
  colours they were but readable, and they are re-baked on a theme switch
  rather than at the next start. The same applies in light mode on a dark
  desktop theme.

## Migration notes

- On the first start after upgrading, folders in your mods directory that are
  in no modlist appear as new rows, switched off. Nothing changes what the game
  loads until you tick them; remove a row you don't want and it is not offered
  again.
- The plain binary keeps its mod lists and settings next to itself. Unpack
  0.75 over the old folder, or copy `modlist_*.txt`, `loadorder_*.txt` and
  `nerevarine_prefs.ini` across, to keep your list. The AppImage keeps its
  state under `~/.local/share/nerevarine` and needs nothing.
