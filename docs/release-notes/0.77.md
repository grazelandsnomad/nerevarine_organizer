# 0.77 release notes

Released 2026-11-22. The cycle where the library moved to a spinning disk and
measured the app honestly. A profile switch took 10, 22 and once 70 seconds
with the window frozen; a first look at a game froze it for fifteen minutes;
and a scan the app had just learned to write down read as "nothing installed"
on an older file, emptying an openmw.cfg and its load order. All of it is
fixed and the reasons are below, because each one was a cost the app had been
paying on every disk and only noticing on a slow one. Also in: Update All no
longer loops back into another check when a mod needs a choice; the update
check is paced and reads what NexusMods says about your allowance instead of
blaming the API key; Cyberpunk 2077 through Heroic starts from the Start
button and shows its launcher from the Launcher button; and both Launcher
buttons stand down while a launcher comes up. And the one fix 0.76.1 was to
carry, which never shipped on its own: switching game and back no longer
claims your mod list changed.

## Bug fixes

- **Switching game and back no longer claims your mod list changed.** The
  plugin load order was one list for the whole window, read from disk only at
  startup, so leaving a game filled it with the next game's plugins and coming
  back judged the first game's deployment against them. The deploy hint said
  the list had changed when nothing had, and it would not clear by itself. The
  order is now held per load-order file, the same file it has always been saved
  to, so the active game's order is whatever its own file holds. The same flaw
  could write one modlist profile's order into another's file when switching
  profiles inside a game; that goes with it.
- **The list appears straight away, even on a cold library.** Deciding whether
  each mod is installed means opening its folder, and on a library kept on a
  spinning disk that measured 103 ms per mod - 42 seconds for 409 of them,
  with the window frozen for all of it. The list now goes up immediately using
  what the previous run wrote down, and any folder nothing is known about is
  opened on a worker afterwards, correcting the few rows that need it.
  Everything that depends on knowing which mods are installed waits for that
  to land, so nothing judges a list the app does not know yet.
- **The folder scan is remembered between runs.** Working out which plugins
  each installed mod ships meant opening every mod folder, and on a 409-mod
  library that measured 16.8 seconds the first time a game was left in a
  session, with another 5.7 reading those plugins' masters. Both are now
  written down and read back, so the work happens once, when something
  actually changes, instead of once per run. What is written down is used as
  it stands: checking it means a stat for every directory the scan ever
  opened, and against a real library that is 7648 of them at 8.1 ms each, or
  62 seconds - which has no business on the interface's thread. Instead the
  app drops what it writes down for any folder it changes itself, and one
  stat of the mods folder catches a mod added or removed while the app was
  closed. Only when that one stat disagrees does a worker go and find which.
- **A mod list full of mods can no longer claim none of them are installed.**
  The field recording whether a mod folder holds anything was added to a file
  format that already existed, and in the older files it read as "empty" - so
  every mod in the library looked uninstalled, the managed section of
  openmw.cfg was written from that, and the plugin load order was pruned to
  nothing. Nothing written down about a folder is now kept separate from
  something measured about it, a recorded "empty" is confirmed before it is
  believed, and the config writer refuses outright to rewrite a file that
  still names populated mod folders when the list claims none.
- **Leaving a game no longer re-derives a load order it already has.** This
  was the last and worst of it: 38 seconds of a profile switch, measured, spent
  asking the filesystem which plugins each of 409 installed mods ships - to
  produce the order already sitting in the file. The order file now records
  what it was built from, so when nothing has changed there is nothing to do
  and no folder is read. The first switch after upgrading still pays once,
  because existing files do not carry that record yet; after that it is free.
- **Opening a game's list for the first time is faster too.** Deciding whether
  each mod is installed cost two filesystem round trips per row, and on a
  library of 405 folders that measured 4.1 seconds the first time and 1 ms
  every time after, because the answer sits in the kernel's cache once it has
  been read. It is one round trip now, which is the same answer in half the
  work, and the folders of the games you are not looking at are read in the
  background so that the first switch to them finds them already warm.
- **Switching game or modlist profile is much faster.** The app's own timings
  put one switch on a 438-row list at 620 ms, and a first switch after
  starting up at 10, 22 and even 70 seconds, all of it freezing the window.
  Most of that was work whose result was thrown away: the dependency scan
  rewrote three values per row that had not changed, and each one cost two
  full passes over every row; the save on the way out rewrote the config of
  the game being left and re-decorated rows the switch was about to destroy;
  the plugin order was re-sorted, which re-read every plugin file, only to
  find it had not moved; and the config sync re-read every enabled plugin's
  header instead of using the copies it already had. All four are fixed.

- **Update All asks which file instead of quietly doing nothing.** A mod with
  several main files on its Nexus page and no record of which one you
  installed could not be updated automatically. Update All gave up on it, and
  because the toolbar then stopped counting it, the button went back to
  reading "Check Updates" - so the obvious next click checked all your mods
  again rather than retrying the one. Each check is one request per installed
  mod, and a few rounds of that is enough for NexusMods to start refusing.
  Now it opens the file picker, and turning it down leaves the mod's arrow in
  place without inviting another check.
- **Checking for updates is paced, remembered and honest about its limits.**
  The check used to fire one request per installed mod all at once - 409 of
  them together on a large list. It now goes out at about five a second, the
  toolbar counts its progress and refuses to start a second check on top of a
  running one, and each mod remembers when its page was last read so a second
  check within a few hours costs almost nothing. Mods → Check for Updates
  (all) ignores that window when you know better. The app also reads what
  NexusMods says about your remaining allowance: it stops before spending the
  last of it, warns when it runs low, and a refusal now says when you can try
  again instead of telling you to check an API key that was never the problem.
- **Cyberpunk 2077 through Heroic starts, and its Launcher button is back.**
  Start used to hand the game to Heroic over a `heroic://` link and count the
  launch as done the moment the desktop accepted it, so when Heroic did
  nothing the button sat on Running and the log said nothing at all. Start
  now runs the game's own exe itself, in the prefix Heroic made, with the
  runner Heroic recorded and the environment Heroic sets, and the launch
  watchdog is armed so a game that never appears is reported. The game's
  launcher, REDprelauncher, is now named as such, which is what the Launcher
  button runs: the two buttons mean different things for this game as they
  do for every other, where before the Launcher button was hidden for
  Cyberpunk and Start could not skip the prelauncher. Either way the log now
  names the exe, the prefix, the runner and what was tried, so a failure has
  something to read. Asking Heroic stays as the fallback when no prefix or
  runner can be found.
- **The Launcher button says "Launching…" and refuses clicks while the
  launcher is up.** Cyberpunk's REDprelauncher takes a while to show under
  Proton, and every click in that gap started another one. The button now
  stands down from the click, as Start does, and comes back a few seconds
  after the launcher closes - or after it has started the game and quit. The
  Morrowind profile's Launcher button does the same around openmw-launcher.

## Migration notes

- **The first switch into each game pays once.** The written-down folder scan
  and the load order's record of what it was built from are new in this
  version, so a game has nothing on file until you have opened it once. That
  first switch does the old work - a few seconds on a solid-state disk, up to
  a minute on a spinning one - and every switch after it reads the result.
  Nothing to do.
- The plain binary keeps its mod lists and settings next to itself. Unpack
  0.77 over the old folder, or copy `modlist_*.txt`, `loadorder_*.txt` and
  `nerevarine_prefs.ini` across, to keep your list. The AppImage keeps its
  state under `~/.local/share/nerevarine` and needs nothing.
