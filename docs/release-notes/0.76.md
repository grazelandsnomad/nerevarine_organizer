# 0.76 release notes

_In development._ Changes land here as they're committed; this file becomes the
GitHub release body when `v0.76` is tagged (release.yml reads it by version).

## New features

- **Start says Running while the game is up.** Pressing it left the button
  looking exactly as before, so nothing stopped a second and third click, and
  each one launched the game again. It now goes grey, reads Running and
  refuses clicks for as long as the app knows a launch is under way, which
  starts at the click rather than after it: the deploy-on-launch and the wait
  for Steam both happen in between, and both used to be clickable. It comes
  back on its own - the moment OpenMW quits, when the launch watch reaches a
  verdict, or after half a minute for a launch nothing can watch, such as one
  handed to Heroic. Switching game clears it too.

- **A download for a game you have no profile for offers to add it.** Clicking
  Mod Manager Download on, say, a Cyberpunk 2077 mod while the Morrowind
  profile was open explained the problem and then stopped: the only choices
  were to install the files into a list the game will never read, or to give
  up. The way forward existed but lived somewhere else entirely, in the game
  menu. That dialog now offers to add the game, find the install, make its mod
  list and put the mod there, leaving the list you were looking at alone. If
  you back out of finding the game, the install is abandoned rather than
  falling back to the wrong list.
- **Cyberpunk 2077 is a normal entry in the game menu.** It shipped behind
  Settings, Show all games, pending a run against a real install. That run has
  happened, on a GOG copy through Heroic, so it is pinned like the rest. Its
  deploy is still the least travelled: the overlay has not been exercised on
  real mod archives yet.

- **Diagnose Last OpenMW Run reads missing-object errors.** OpenMW's
  `Cell reference "..." is not found!` names a record id, not a file, so every
  one of them used to land in the catch-all bucket as an unexplained error -
  and because each repeat carried a new timestamp, a single message could
  spend the whole ten-item allowance and hide everything after it. They are now
  their own class, collapsed to one entry per object with a `×N` repeat count,
  and the mod is named by searching the installed plugins for the id, so the
  report says which mod places the object and that something in the load order
  is missing or disabled.


## Bug fixes

- **A Cyberpunk mod that is one bare `.archive` now reaches the game.** Most
  single-file mods for it ship exactly that, with no folders around it, and the
  overlay deploy mirrored the mod folder as it stood: the archive landed at the
  install root, which the engine never reads, and the deploy reported success
  with no errors. A `.archive` or `.xl` now goes to `archive/pc/mod` and a
  loose `.reds` to `r6/scripts`, from whatever depth the mod left it at, while
  a mod that already ships the full `archive/pc/mod/` path is untouched. If you
  already have one deployed in the wrong place, Deploy again.

- **A GOG game's Proton prefix is found, so mod loaders are actually enabled.**
  The wrapper DLLs that RED4ext and Cyber Engine Tweaks ship do nothing under
  Wine until the prefix is told to prefer them, and the hunt for that prefix
  only ever looked in Steam's `compatdata`. On a Cyberpunk 2077 copy installed
  through Heroic the deploy therefore put every file in the right place and
  registered nothing, leaving the loaders inert with no error anywhere. The
  prefix Heroic keeps for the game is now read from its own config and used
  when Steam has none. Measured on a real install, which is also the first
  time this game's deploy has been run outside a mock, and covered by a test
  that deploys a GOG-shaped copy with no Steam prefix anywhere and checks the
  override lands in Heroic's registry.

- **Move Mod Library moves the whole library.** It used to move only the
  folders a modlist row pointed at directly, so a library of download folders
  (the row holds a `Data Files` sub-folder) and any folder no row points at
  stayed behind while the move still reported success and repointed the
  profile to the new disk. It now moves every folder in the library, carries
  each row with its folder keeping the tail of its path, and the summary says
  what is still in the old folder instead of claiming a clean move.
- Mods → Move Mod Library…: picking the root of a disk now moves the library
  there *as a folder* (`/mnt/disk/<library name>`) instead of strewing every
  mod folder over the drive root and making the root the mods directory. The
  confirmation says exactly where the mods will land, and the menu entry
  carries the toolbar's ⇄ symbol.
