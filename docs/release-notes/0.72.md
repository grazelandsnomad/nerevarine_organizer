# 0.72 release notes

_In development._ Changes land here as they're committed; this file becomes the
GitHub release body when `v0.72` is tagged (release.yml reads it by version).

## New features

- **Oblivion Remastered.** A Steam install is found on its own, and Deploy
  works for it. The remaster is the original engine inside Unreal 5, and three
  things differ from every other Bethesda game here. Its data sits five
  folders deep, in `OblivionRemastered/Content/Dev/ObvData/Data`. Its
  `Plugins.txt` lives in that Data folder and already lists the base game,
  the DLCs and the remaster's own `AltarESPMain.esp`, so a deploy adds your
  mods' plugins after that list instead of writing over it - done the usual
  way, the game would have lost its own. And some of its mods are not
  Bethesda files at all: Unreal `.pak` mods go to `Content/Paks/~mods`
  (UE4SS blueprint mods to `LogicMods`), OBSE64 plugins to
  `Binaries/Win64/OBSE`, and the OBSE64 loader beside the real game exe,
  wherever in the archive the mod kept them. Removing the deployment takes
  all of it back out and restores the game's list.

- **Mod-list backups now survive a clean of a source checkout.** A build run
  from a git clone keeps its state next to the binary, inside the checkout -
  and so did every backup of it, so one `git clean -xdf` took the mod lists
  and all twenty of their snapshots with them. Every snapshot is now also
  written outside the checkout, to
  `~/.local/share/nerevarine/Nerevarine Organizer/backups/`, and **Restore
  Modlist Backup** lists both places, so after a clean the button you already
  know brings the list back. The copy outside only takes a slot when the list
  actually changed, so the saves a session makes without changing anything
  cannot rotate the lost list out of it. A banner says all this once per
  checkout. AppImage and installed copies already keep their state outside
  any checkout and are unchanged.

## Bug fixes

- **"Your mod list has changed since it was last deployed" now means it.**
  It used to compare file times, and every save touches the list file -
  including the ones that change nothing, like switching games or quitting -
  so a list deployed and left alone claimed to have changed after the next
  restart. A deploy now records what it was made from (the enabled mods, in
  order, and the plugin load order), and the banner compares against that;
  reinstalling a mod into the same folder still counts as a change. A
  deployment made before this version keeps the old check until you deploy it
  once more.
- **Switching game no longer carries the old game's banner and count along.**
  Creating a new game straight after deploying another one showed the
  previous game's "changed since it was last deployed" over the new, empty
  list, with its "150 / 150 mods active" still in the corner. A game or
  profile that has never been saved now opens as a proper empty list.
- **Deploying during a temporary Size or Date sort uses your real order.** It
  deployed in the sorted order, which decides which mod wins a conflict.
- **Building from source no longer resets `nerevarine_prefs.ini`.** The file
  invites you to edit it, and `build.sh` copied the shipped one over it on
  every build, so a customised zoom range lasted until the next build. It is
  now written only when missing.

## Migration notes

- **Source builds keep a second copy of each mod-list backup**, under
  `~/.local/share/nerevarine/Nerevarine Organizer/backups/<checkout>-<id>/`,
  with the same 20-snapshot limit. The largest list measured here is 106 KB,
  so that is a few MB at most. Nothing is written there for AppImage or
  installed builds.
